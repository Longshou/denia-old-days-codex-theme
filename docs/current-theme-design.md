## 运行架构

主题分为两层：

1. Base Theme 提供明亮暖纸背景。
2. 可卸载 Sidecar 通过本地 CDP 注入首页、状态美术、卡片和输入区装饰。

Sidecar 不修改 Codex 应用包、签名、账户、模型或 API 配置，不发起运行时网络请求。

启动链路必须确保 LaunchAgent 在 `bootstrap` 后实际 `kickstart`，并以实时渲染器验证结果作为成功依据。

## 首页

- 首页采用《旧日斑斓》暖色剧情画面、拍立得、虹彩泡泡和四张手账建议卡。
- 侧栏品牌卡只在首页出现。
- 首页允许开屏式首屏；输入区可以在下拉后的工作区域出现。
- 窄屏调整构图，不替换成孤立全身立绘。
- 建议卡的父槽位始终紧跟 hero；原生动作暂时不足四个时只移除卡组，保留空槽的最近有效高度，不制造按钮、角色、标签、焦点或指针目标。
- 卡组只能代理当前四个真实原生动作，顺序、禁用态和点击映射随当前原生按钮重新绑定。首次晚到挂载分别以桌面一行、中屏两行、窄屏四行的非零高度占位，避免工作区跳动。

## 任务页与原生布局

- 不修改任务页 `main`、分栏、输入框或原生审批卡的几何尺寸。
- 人物图是不参与布局的右侧背景装饰层。
- 原生内容、输入框和权限卡必须始终位于装饰层之上。
- 小于 `920px` 时隐藏右侧美术，优先保证工作区。

## 原生右侧栏

- 首页和任务页共用几何识别，但使用不同视觉强度。
- 高置信打开时，侧栏使用暖纸、青灰分界和高不透明功能表面。
- 首页侧栏不显示人物；任务侧栏用状态色表达情绪，不让人物穿过原生内容。
- 右侧栏关闭时，任务状态人物栏恢复。
- 检测不确定或宽度小于 920px 时隐藏人物并不触碰原生侧栏。
- 不修改侧栏宽度、滚动、分栏、按钮、快捷键、审批卡或输入框几何。

## 状态与美术

| 状态 | 美术 |
| --- | --- |
| `staged` | 暖色花园泡泡图，低强度等待 |
| `working` | 同一暖色图，提高对比并轻微靠近工作区 |
| `approval` | 官方双形态竖幅，表达等待用户决定 |
| `error` | 独立周年插画展图，保留完整无笑意正脸与抬臂动势 |
| `complete` | 明快周年近景 |

状态判断优先级为：

1. 可见错误；
2. 可见审批、权限或确认界面；
3. 正在工作；
4. 已完成；
5. 等待。

任何可见的原生权限卡、批准按钮或确认控件都必须被识别为 `approval`，即使页面已经存在助手消息。审批检测不能只依赖 `role="dialog"` 或旧版 `data-state` 属性。

错误状态优先读取可见的结构化错误标记和 alert；只有最新助手消息中明确的命令失败段落（失败前缀、`command not found` 与非零退出状态同时存在）才作为文本兜底，普通讨论、用户消息、代码块和旧消息不会触发错误态。

## 动效与可访问性

- 状态图使用受控透明度和位移过渡，不改变页面布局。
- 支持减少动态效果和减少透明度偏好。
- 装饰节点不接管指针事件。
- 原生按钮、审批交互和键盘焦点保持可用。
- MutationObserver 保留原生 `style`、`class`、ARIA、状态和 `data-testid` 观察；主题自身节点、纯主题 class token 变化和仅含主题节点的 child-list 会被过滤。稳定首页与任务页在等价两秒观察窗口内最多增加四次 refresh。

## 验证

清理和后续修改必须验证：

- 源文件与素材哈希检查通过。
- Sidecar 静态与行为校验通过。
- 本地 Kaboo 包可以重新生成，ZIP 与目录清单一致。
- Base Theme 和 Sidecar 的实时验证均通过。
- 首页与任务页没有水平溢出。
- 审批卡出现时状态为 `approval`，右栏使用审批专用图片。
- 建议卡重挂载前后槽位高度不变，空槽没有交互后代；稳定首页与任务页的 refresh 增量不超过四次。

除非用户明确要求，不上传、不推送、不创建 PR、不发布 Registry，也不擅自重启 Codex。
