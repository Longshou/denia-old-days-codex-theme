# 达妮娅主题：审批与错误状态视觉分离设计

## 背景

现有实现让 `approval` 与 `error` 共用 `denia-dark-direct-gaze.jpg`，仅通过透明度、色调、边缘和轻微缩放区分。实际体验中，两种状态仍形成同一个视觉记忆，用户无法在第一眼通过人物情绪和构图区分状态。

本设计采用已确认的 D + P1：审批使用明暗双形态周年竖图，错误切换为另一张无笑意、带失衡感的官方周年发布图。

本设计覆盖本地主题实现与截图验证，不包含上传远程仓库或 Kaboo Registry。

## 设计意图

目标不是单纯“换一张图”，而是建立两种不同的状态职责：

- `approval`：明暗两面同时在场，停顿并等待用户判断。
- `error`：失衡、警觉、需要用户介入。

审批位于明暗形态的交界，错误进入明显的暗色失衡状态。两态通过人物姿态、画面运动方向和空间稳定性区分，而不是把错误态简单做得更暗。

设计参数：

- `DESIGN_VARIANCE = 5`：沿用当前手账工作区和固定右侧艺术栏，只调整状态艺术映射。
- `MOTION_INTENSITY = 5`：保留可感知但克制的跨图过渡；错误态不使用持续抖动。
- `VISUAL_DENSITY = 4`：艺术栏承载角色氛围，正文工作区继续保持清晰、低干扰。
- 技术方向：原生 CSS 与现有 Sidecar 状态扩展，不引入新的 UI 依赖。

## 素材职责

### 审批

- 素材源：`source-media/official-published-x/HIWo1PrbMAA7jS-.jpg`
- 来源：官方周年竖幅贺图。
- 构图：明色形态位于前景并看向用户，暗色形态作为上方背景注视；保留双形态、泡泡和局部权杖。
- 情绪：明色形态温和但不庆祝，暗色形态保持审视。
- 视觉职责：让审批看起来像“她的两面都在等待你的决定”，同时把双形态设定放在真正需要用户选择的场景里。

审批态只使用原图中部人物区域。左上官方标识、底部版权文字和过多空白装饰必须处于裁切区外。

### 错误

- 素材源：`source-media/official-published-x/HJIw0-rbcAAU68K.jpg`
- 来源：官方周年插画展发布图。
- 构图：人物处于失重姿态，手臂向上伸出；运行时窄栏优先保全完整脸部，再保留抬臂动势与局部暗色剪影。
- 情绪：失衡、警觉、无笑意。
- 视觉职责：让错误看起来像“画面秩序已经被打断，需要处理”。

错误态只使用原图中央插画区域。外层相框标题、署名和装饰文字必须完全处于裁切区外，不能进入 Codex 工作界面。

## 状态映射

实现后，状态艺术族由共享的一组拆成两个独立角色：

| 状态 | 艺术族 | 目标透明度 | 色彩倾向 | 主要识别信号 |
| --- | --- | ---: | --- | --- |
| `approval` | `taskApproval` | `.40–.46` | 蓝紫与柔粉 | 双形态同框、前景正面注视 |
| `error` | `taskError` | `.52–.58` | 深紫与窄幅洋红 | 完整无笑意正脸、抬臂动势、剪影 |

状态优先级维持 `error > approval > working > complete > staged`，只更换状态与艺术资源的映射，不修改检测语义。

## 裁切与界面衔接

- 固定右侧艺术栏的宽度和定位保持现状，避免影响 Codex 内容布局。
- 审批以明色形态脸部和上方暗色形态为双锚点；初始裁切采用约 `background-size: auto 140%`、`background-position: 50% 15%`，再以实际 Codex 截图微调。
- 错误以人物完整正脸作为首要锚点，抬臂动作作为次要动势；以实际 Codex 截图为准微调，不为强留手部而切掉额头或下颌。
- 艺术栏左缘继续使用浅色渐变与工作区衔接，人物和正文之间必须有明确层级，不能糅成整页壁纸。
- 错误态的洋红只作为边缘与状态 token，不将正文工作区整体染紫或压暗。
- 窄窗口下，审批优先保住明色形态脸部和暗色形态眼神，错误优先保住人物脸部、其次保住伸手动作；任何情况下都不能露出原图外围文字。

## 状态过渡

- `working → approval`：暖色工作图退出，审批注视图在 `220–320ms` 内进入。
- `approval → error`：审批图淡出、错误图淡入，跨图过渡控制在 `180–240ms`；洋红边缘在错误图进入前半段出现。
- `error → working`：错误图与洋红边缘一起退出，不保留错误残影。
- `error → complete`：先降低错误色偏，再进入完成态暖色素材，避免从深紫直接闪成暖金。
- `prefers-reduced-motion: reduce`：取消位移和缩放，仅保留不超过 `120ms` 的透明度切换。

错误态不使用循环抖动、持续 glitch 或高频闪烁。图像自身已经包含足够的异常叙事，UI 动效只负责状态切换。

## 资源与构建

- 将审批态源图生成一份面向 Sidecar 的本地优化资源，例如 `denia-approval-dual-form.jpg`。
- 将错误态源图生成一份面向 Sidecar 的本地优化资源，例如 `denia-error-reaching.jpg`。
- 构建脚本为 `taskApproval` 与 `taskError` 分别注入数据，不再让两态共用 `taskDark`。
- 保持离线可用；运行时不请求外部图片地址。
- 不把未使用候选图、临时对比页或抓取缓存打入主题包。

## 验收标准

1. 审批与错误截图并排时，即使隐藏状态文字，也能通过人物姿态与构图在第一眼区分。
2. 审批同时保留明暗双形态，明色形态保持视线互动，但不误读为成功或庆祝。
3. 错误图中人物完整正脸无笑意，仍能读出失重与抬臂动势，但不会压过正文或输入框。
4. 默认窗口与窄窗口均不出现原图标题、署名、版权文字或白色外框。
5. 两态左侧工作区保持浅色、可读，并与右侧艺术栏形成稳定分区。
6. `approval → error` 使用真实跨图过渡，不再依靠同图缩放制造差异。
7. 状态检测优先级、主题离线能力和已有完成/工作态不回归。
8. 至少重新产出并检查 `task-approval.png`、`task-error.png`、`task-working-to-approval-350ms.png` 和一张错误退出截图。

## 风险与自审结论

审批源图的风险是双形态纵向距离较大：裁切过近会丢失暗色形态，裁切过远则人物脸部过小。验收以明色形态脸部可读、暗色形态眼神可辨为下限；若固定侧栏无法同时满足，不通过重复缩放勉强修补，而应生成专门的无损裁切资源。

错误源图的风险是包含完整展览相框和文字。设计不允许靠遮罩“勉强盖住”，而是要求在所有目标宽度上通过裁切彻底排除。用户复核后明确将完整正脸置于手部之前；若实际侧栏无法同时保住完整正脸、抬臂动势和无文字区域，应先舍弃手部细节，再重新选择错误素材，不能继续切掉脸部。

D + P1 的优势是审批明确承载角色双形态，错误再从“双面审视”进入“秩序失衡”，状态叙事更完整。相较暖色花园候选，它不会与完成态争夺情绪职责；相较暗色晶球候选，它更直接回应用户希望兼顾两种形态的要求。

本设计取代 `2026-07-23-denia-state-transition-design.md` 中“审批与错误共用同一暗色近景”的相关约定，其余状态设计继续沿用。
