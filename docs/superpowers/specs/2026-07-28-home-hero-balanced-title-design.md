# 首页横幅标题均衡断行

## 现状与根因

当前 `1512×863px` 窗口使用低高度桌面横幅：

- 横幅宽 `1160px`，水平内边距共 `72px`，栏间距为 `36px`。
- 左栏约 `463px`，扣除文字区右内边距后，标题实际可用宽度约 `435px`。
- 标题字号为 `48px`，共 11 个中文字符。
- 标题没有平衡断行规则，浏览器按可用宽度尽量填满首行，形成 9＋2 的断行。

问题来自标题自身的断行策略，不是横幅宽度、图片尺寸或主栏对齐。

## 方案比较

### 方案一：CSS 平衡断行

在 `.denia-old-days-ds-hero h1` 上增加：

```css
text-wrap: balance;
line-break: strict;
```

当前窗口下标题按 6＋5 排为：

```text
今天要把什么
写进手账？
```

`text-wrap: balance` 平衡两行长度，`line-break: strict` 保持中文标点与正文的正常关系。宽度足够时仍允许单行，窄屏继续按现有容器宽度响应。

### 方案二：扩大左侧文字栏

调整横幅网格比例可以减少尾行字符，但会压缩右侧照片，破坏上一轮已经验收的 `500px` 图片尺寸和主栏布局。拒绝采用。

### 方案三：写死换行

在运行时文案中插入 `<br>` 可以固定断点，但需要修改 JavaScript 和标题结构，且不适合不同窗口宽度。拒绝采用。

## 视觉设计

- 保留现有字体、字号、字重、行高和字距。
- 保留现有横幅宽高、内边距、网格比例、图片尺寸、配色、圆角和阴影。
- 保留眉题与状态标签的内容和位置。
- 只把桌面标题从明显失衡的 9＋2 调整为接近等长的 6＋5。
- 不增加新装饰、动画或交互。

## 变更边界

允许修改：

- `sidecar/src/denia-old-days-extension.css` 中 `.denia-old-days-ds-hero h1` 的断行属性。
- `sidecar/tests/validate.mjs` 中该选择器的 CSS 契约。
- 本设计文档和对应实施计划。

禁止修改：

- 横幅网格、尺寸、内边距、图片和泡泡。
- 首页文案和运行时 JavaScript。
- 首页背景、原生输入区、项目选择器和侧栏。
- 任务页背景、人物栏、状态映射和输入区。
- `art/`、`theme/`、`sidecar/assets/`、清单和脚本。

## 测试与验收

先增加失败断言，再修改 CSS：

- 基础标题规则包含 `text-wrap: balance`。
- 基础标题规则包含 `line-break: strict`。
- 现有横幅尺寸和响应式断言保持不变。
- `1512×863px` 实机下标题为两行，字符数为 6＋5。
- 横幅、图片、原生输入框和任务页实测尺寸不变。
- `npm run check`、Kaboo 构建、首页验证和任务页回归通过。
