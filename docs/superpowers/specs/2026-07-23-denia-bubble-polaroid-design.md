# 达妮娅泡泡拍立得与双形态视觉设计

日期：2026-07-23

状态：已完成方向确认，等待书面规格复核

## 1. 设计判断

这是对现有 Codex 主题的定向重设计，不改变信息结构和原生交互。主题继续以《旧日斑斓》的记忆手账为叙事基础，但减少通用贴纸语言，强化达妮娅自身的泡泡、珊瑚发色、水青布景和双形态色彩。

设计参数：

- `DESIGN_VARIANCE: 7`：保留非对称手账构图，但操作区保持稳定。
- `MOTION_INTENSITY: 3`：只使用入场显影和状态过渡，不加入持续漂浮动画。
- `VISUAL_DENSITY: 4`：保留 Codex 日常工作密度，不把主题做成展示海报。

## 2. 目标

1. 把首页的星形、皇冠状贴纸和花形装饰替换为达妮娅语境更明确的透明泡泡。
2. 把官方《旧日斑斓》画面处理成 P2「经典泡泡拍立得」，解决图片与工作界面割裂的问题。
3. 让亮态与暗态分别对应布景之形和幻灭之形，并在不同任务状态中有明确分工。
4. 保持人物美术、文字、代码、Diff、建议按钮和输入区之间的清晰边界。
5. 完成后提供多张截图，展示首页、任务状态、完成态和 Registry 能力。

## 3. 非目标

- 不改变原生按钮的语义和事件绑定。
- 不改变项目选择、输入、附件、发送、工具记录和助手回复的原生行为。
- 不增加远程图片请求。
- 不新增未经确认的角色设定、剧情名词或翻译。
- 不把整个工作区切换成暗色主题。
- 本轮不上传远程仓库，不发布 Registry。

## 4. 首页视觉

### 4.1 装饰语言

- 移除星形、皇冠状贴纸和花形贴纸。
- 使用三组以内的泡泡，每组由一大一小或一大两小组成。
- 泡泡位于相片外缘、书页边缘和大面积留白处。
- 泡泡不得覆盖标题、说明、建议卡、项目入口、输入区或主要人物面部。
- 泡泡表面使用水青透明层、珊瑚粉暗面和白色高光，不使用霓虹外发光。
- 泡泡默认静止，只随首页整体入场轻微显影。

### 4.2 P2 经典泡泡拍立得

首页右侧继续使用官方《旧日斑斓》正脸画面，构图改为 P2：

- 暖白即时相纸，不使用纯白 UI 卡片质感。
- 相纸具有细颗粒、轻微色差和可见纸张厚度。
- 上、左、右边距较窄，下边明显加厚，形成经典拍立得比例。
- 相纸整体轻微逆时针旋转，使用很弱的翘角或纸张变形。
- 图片内缘使用低透明度深靛紫细边，作为幻灭之形的伏笔。
- 外部阴影偏水青灰，不使用纯黑阴影。
- 水青与珊瑚泡泡跨越相纸边缘和纸面留白，负责视觉过渡。
- 相片与操作区保持独立，不让图像渐变侵入文字和按钮。

### 4.3 首页层级

首页保持左右结构：

- 左侧为标题、说明与原生动作映射。
- 右侧为拍立得主视觉。
- 中央装订结构继续提供手账识别，但降低对比度，避免和人物争夺注意力。
- 明亮背景以水青为主，珊瑚粉呼应发色，暖金只用于主要焦点。
- 首页不直接展开大面积暗色美术。

## 5. 双形态配色

### 5.1 亮态

适用场景：

- 首页
- `staged`
- `complete`

颜色分工：

- 水青：背景、边线、泡泡主体和聚焦环。
- 珊瑚粉：泡泡暗面、少量状态提示和人物呼应色。
- 暖金：发送按钮、完成态重点和少量视觉焦点。
- 深靛紫：只以 5% 至 10% 的视觉占比出现在拍立得内缘或极弱反光中。

### 5.2 暗态

适用场景：

- `working`
- `approval`
- `error`

状态递进：

- `working`：阅读区外侧出现低透明度深靛紫画轨，保留水青接缝。
- `approval`：画轨透明度提高，加入克制的紫粉提示。
- `error`：画轨透明度再次提高，允许洋红和警示红更明确，但不覆盖内容。
- `complete`：隐藏暗色画轨，恢复水青、珊瑚粉和暖金的完成显影。

暗色人物美术始终位于阅读列外侧，不能成为正文、代码、Diff 或输入控件的背景。

## 6. 工作界面

### 6.1 首页建议卡与输入区

- 建议卡保持四个真实动作的语义映射和原生事件代理。
- 卡片继续使用统一的柔和圆角，不加入贴纸式不规则边框。
- 卡片装饰从通用圆点改为低对比泡泡切片。
- 输入区保持独立信纸表面，焦点环和发送按钮满足清晰对比。

### 6.2 任务页

- 观察记录继续使用浅水青虚线边界。
- working 状态只显示处理中内容，不混入完成态文案。
- approval 和 error 通过右侧画轨、品牌标识与状态色表达，不改写原生消息。
- complete 使用暖金与珊瑚粉完成显影，突出最新一条助手回复。
- 亮态和暗态之间通过状态变化切换，不在同一内容区域混合两套大面积背景。

## 7. 响应式规则

- 宽屏：展示横向 P2 拍立得与完整泡泡过渡。
- 中等窗口：使用包内紧凑立绘，置于窄版拍立得中；减少泡泡数量和阴影强度。
- 小于 920px：隐藏人物相片和任务画轨，仅保留少量背景泡泡、亮态色彩和完整工作功能。
- 高变化度构图在小窗口回到单列，不允许产生横向溢出。

## 8. 动效与可访问性

- 首页只使用一次入场显影，动画只改变 `transform`、`opacity` 和饱和度。
- 状态切换只使用画轨透明度与位移过渡。
- 不使用持续漂浮的泡泡动画。
- `prefers-reduced-motion: reduce` 时关闭入场和状态过渡。
- `prefers-reduced-transparency: reduce` 时使用实色相纸和泡泡替代半透明效果。
- 所有原生控件保留键盘导航和明显聚焦环。
- 主题装饰节点保持 `pointer-events: none`。

## 9. 美术与资源边界

- 继续使用当前已确认来源的三套包内美术：
  - 《旧日斑斓》亮态正脸画面
  - 达妮娅暗态横幅
  - 达妮娅透明紧凑立绘
- 不新增远程资源。
- 不在运行时请求图片。
- 新增的泡泡、相纸纹理与过渡由主题自己的 SVG 或 CSS 生成。
- 生成物哈希、渲染参数和来源记录同步更新。

## 11. 验证要求

- 先写失败测试，再修改正式主题源码。
- 源码检查必须确认旧星形、皇冠状和花形装饰不再进入首页输出。
- 源码检查必须确认 P2 相纸具有厚下边、纸张纹理和深靛紫内缘。
- Sidecar 验证必须覆盖首页主视觉使用包内亮态美术。
- Sidecar 验证必须继续覆盖 working、approval、error 和 complete 的画轨状态。
- 预览生成必须可复现，连续两次构建的 ZIP 字节一致。
- 前端 Registry 测试必须继续覆盖 15 项能力标题。
- 最终执行格式、Lint、类型、脚本语法、Sidecar、打包器、ZIP 完整性和哈希校验。

## 12. 验收标准

1. 首页不再出现星形、皇冠状或花形贴纸。
2. 官方正脸画面呈现为 P2 经典泡泡拍立得，而不是白色 UI 卡片。
3. 相片、工作区和背景之间存在清晰但柔和的层级过渡。
4. 首页颜色明显更接近达妮娅，水青、珊瑚粉和少量暖金有明确分工。
5. 暗色只在 working、approval 和 error 中递进出现，complete 回到亮态。
6. 人物美术不覆盖文字、代码、Diff、按钮或输入区。
7. 宽屏、中等窗口和小窗口均无横向溢出。
8. 所有资源保持包内加载，停止或卸载后可以完整清理。
9. 提供第 10 节规定的多张能力截图或明确标注的预览，并如实说明实机采集边界。
