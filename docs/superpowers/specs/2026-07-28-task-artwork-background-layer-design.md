# 任务人物图改为持久背景层

## 问题

任务页右侧人物图会在以下操作发生时整张消失：

- 打开底部面板。
- 打开置顶摘要。
- 打开右侧栏。

人物图由独立的 `#denia-old-days-ds-chrome` 承载。该节点位于 `body` 下，使用固定定位和
`z-index: 2`。任务内容、置顶摘要、底部面板和右侧栏位于另一个原生堆叠上下文中。

当前 CSS 在右侧栏非关闭或聚合工作面打开时，将人物栏设为：

```css
opacity: 0;
visibility: hidden;
```

这条规则避免人物覆盖原生面板，但会隐藏整张人物图。底部面板只占用底部空间，也会触发同一条
规则并撤销人物栏对应的正文横向对齐。

## 实机层级

当前 Codex 任务页的原生层级为：

- 置顶摘要位于任务内容内的 `z-40` 浮层。
- 右侧栏位于任务工作区内的 `z-41` 层。
- 底部面板使用独立的不透明工作表面，展开时覆盖任务页底部。
- 任务 `main` 已使用 `isolation: isolate`。

人物栏挂在 `body` 下，无法直接使用这些原生层级完成遮挡。

## 方案比较

### 任务 `main` 内的背景层

将 `#denia-old-days-ds-chrome` 挂到当前任务 `main`，放在 `main` 背景之上、所有任务内容之下。
原生摘要、底栏和右侧栏按自身矩形自然覆盖人物图。

此方案不读取面板尺寸，不修改原生面板层级，也不增加面板切换逻辑。采用此方案。

### 保持 `body` 挂载并动态裁切

按摘要、底栏和右侧栏的实时矩形计算 `clip-path`。该方案需要在面板动画期间读取几何并更新裁切，
会扩大布局计算和状态组合。不采用。

### 分别装饰三个原生面板

为三个面板查找宿主节点并补充主题 class 或层级。该方案依赖 Codex 内部 DOM，增加
MutationObserver 分类和清理范围。不采用。

## 背景层

- `#denia-old-days-ds-chrome` 的任务页宿主改为当前 `main.main-surface`。
- `main` 先绘制自身背景，再绘制负层级中的人物栏，其他任务内容位于人物栏之上。
- 任务正文、输入框、置顶摘要、底部面板和右侧栏继续使用原生层级。
- 人物栏保持固定右对齐、当前宽度、顶部偏移、遮罩、透明度和 `pointer-events: none`。
- 置顶摘要只覆盖右上方与自身相交的区域。
- 底部面板只覆盖底部与自身相交的区域。
- 右侧栏覆盖其占用的完整右侧区域。
- 多个组件同时打开时，人物图被这些组件矩形的并集覆盖。
- 组件关闭后直接露出当前人物图，不执行显隐淡入。

任务 `main` 尚未出现或正在被路由替换时，不显示未归属到任务堆叠上下文的人物栏。新
`main` 出现后复用或重新挂载唯一的 `#denia-old-days-ds-chrome`。主题清理仍删除该节点。

首页继续使用现有首页视觉，首页中的任务人物栏保持 `display: none`。视口小于 `920px` 时仍隐藏人物栏。

## 工作面状态

保留以下独立标记：

- `data-denia-summary-state`
- `data-denia-bottom-panel-state`
- `data-denia-sidebar-state`
- `data-denia-work-surface-state`

`data-denia-work-surface-state` 只表示横向任务空间是否被右侧组件占用：

```text
summary=open 或 sidebar=非关闭可信状态 -> open
其他情况 -> closed
```

底部面板不再单独把聚合状态切成 `open`。`data-denia-bottom-panel-state` 仍即时同步原生按钮状态。

| 置顶摘要 | 底部面板 | 右侧栏 | 聚合状态 | 人物图 | 正文横向规则 |
| --- | --- | --- | --- | --- | --- |
| 关闭 | 关闭 | 关闭 | `closed` | 完整可见 | 保留人物栏空间 |
| 关闭 | 打开 | 关闭 | `closed` | 底部被覆盖 | 保留人物栏空间 |
| 打开 | 任意 | 关闭 | `open` | 摘要区域被覆盖 | 使用原生剩余空间 |
| 任意 | 任意 | 打开 | `open` | 侧栏区域被覆盖 | 使用原生剩余空间 |

侧栏收起动画使用现有 `sidebar-state`、`sidebar-toggle-state`、摘要状态和底栏状态组合，不修改
已有的 160 毫秒对齐规则。

## 任务状态图片

以下逻辑保持不变：

- `staged` 和 `working` 使用 `taskWarm`。
- `approval` 使用 `taskApproval`。
- `error` 使用 `taskError`。
- `complete` 使用 `taskComplete`。
- 同图状态只调整强度。
- 跨图状态继续使用 current/next 双层交叉过渡。
- 减少动态效果时继续立即切换。
- 图片继续使用启动时创建的本地对象 URL，不重新请求或解码远程资源。

面板状态不参与 `syncStateArt()` 的图片选择。人物被组件覆盖期间，任务状态变化仍更新 active
layer、`data-denia-art-family` 和 `--denia-state-art-opacity`。组件关闭时显示最新状态，不重新创建
人物节点，不回退到打开组件前的图片。

## 性能边界

- 不新增 MutationObserver、ResizeObserver、滚动监听或动画帧循环。
- 不在面板切换路径读取面板矩形、调用 `getBoundingClientRect()` 或更新 `clip-path`。
- 不因面板开关创建、删除或重新配置人物图片层。
- `#denia-old-days-ds-chrome` 只在任务 `main` 首次出现或被路由替换时挂载。
- 主题自身节点移动继续由现有 owned-subtree 过滤器排除，不能形成刷新反馈环。
- 面板按钮 marker 继续在下一帧前同步，style 动画继续使用现有 80 毫秒尾部刷新。
- 摘要、底栏和右侧栏的六个开关方向在 900 毫秒内的完整刷新次数均不超过 5 次。
- 与原生基线相比，主题不能额外增加超过 1 个 50 毫秒以上长任务。

固定人物栏继续限制在约 `302px × 817px` 的右侧区域。面板展开时允许浏览器对被不透明表面覆盖的
像素执行正常合成，不增加滤镜、模糊或新动画。

## 测试

### 静态样式

- 面板状态选择器不得再为人物栏设置 `opacity: 0` 或 `visibility: hidden`。
- 任务 `main` 内的 chrome 使用背景层层级。
- 首页和小于 `920px` 的隐藏规则继续存在。
- 人物图宽度、顶部偏移、遮罩、状态透明度和过渡参数保持不变。

### 运行时

- chrome 的宿主是当前任务 `main`，重复刷新不产生第二个 chrome。
- 路由替换 `main` 后，旧宿主不残留人物节点，新宿主只有一个 chrome。
- 仅打开底部面板时，底栏状态为 `open`，聚合状态保持 `closed`。
- 打开摘要或右侧栏时，聚合状态为 `open`。
- 摘要、底栏和右侧栏单独或组合切换时，人物节点数、`createdNodes` 和 `artGeneration` 不变。
- 固定任务状态时，面板切换不改变 active art family 和对象 URL。
- 面板打开期间切换任务状态后，active art family 更新；关闭面板后仍为新状态。
- cleanup 删除嵌套在任务 `main` 中的 chrome 和全部现有 marker。

### 实机

- 分别打开置顶摘要、底部面板和右侧栏，人物栏计算样式保持可见。
- 每个原生组件在相交区域位于人物栏之上，文字和交互控件不受人物图影响。
- 组件未覆盖的区域继续显示人物图。
- 仅打开底部面板时，正文和输入区的横向坐标相对关闭状态误差不超过 `1px`。
- 打开摘要或右侧栏时，正文继续在原生剩余空间内布局。
- 人物被覆盖期间触发 `approval`、`error` 和 `complete`，关闭组件后显示对应图片。
- 连续三轮执行摘要、底栏和右侧栏开关，记录完整刷新、最大帧间隔和长任务数量。
- 验证结束后恢复摘要、底栏和右侧栏全部关闭。
- `npm run check`、Kaboo 本地构建、安装后实时验证全部通过。

## 变更范围

允许修改：

- `sidecar/src/denia-old-days-extension.js` 的 chrome 宿主和工作面聚合语义。
- `sidecar/src/denia-old-days-extension.css` 的 chrome 背景层与人物显隐规则。
- `sidecar/tests/validate.mjs` 的样式、运行时、实时验证和性能契约。
- `sidecar/runtime/loader.mjs` 中与实时验证对应的断言。
- 当前设计说明和实施计划。

不修改：

- 人物素材和清单。
- 状态判断优先级、图片映射、透明度、滤镜和交叉过渡。
- 原生摘要、底栏、右侧栏、输入框和正文的尺寸或交互。
- 首页视觉和主题背景配色。
- 安装、卸载、启动、发布和网络行为。

## 验收标准

- 三类组件打开时不再主动隐藏整张人物图。
- 原生组件自然覆盖相交区域，人物图不盖住文字或控件。
- 底部面板单独开关不引起正文横向跳动。
- 任务状态图片在组件打开期间继续更新。
- 面板开关不创建人物节点，不改变固定状态下的图片代次。
- 面板性能不低于现有刷新和长任务预算。
- 首页、窄屏、减少动态效果、减少透明度和主题清理行为不回退。
