# 达妮娅任务状态双形态转场设计

日期：2026-07-23

状态：方案 A 已确认，待实施

本规格取代《达妮娅泡泡拍立得与双形态视觉设计》中“工作态与完成态不显示侧栏美术”的规则。首页设计、拍立得、泡泡和素材来源边界保持不变。

## 设计判断

任务页使用“稳定的浅色手账工作区 + 固定的单画面状态侧栏”。明暗双形态不是两套互不相关的壁纸，而是同一张完整官方舞台原图中的两个角色形态。状态变化只在固定侧栏内发生，不改变 Codex 原生工作区的布局、亮度与交互层级。

- `DESIGN_VARIANCE: 5`
- `MOTION_INTENSITY: 5`
- `VISUAL_DENSITY: 5`

独立审查依据见[任务状态 UI/UX 审查](../../reviews/2026-07-23-denia-state-transition-ui-ux-review.md)。

## 目标

1. 消除 `working`、`complete` 右侧只剩纯色占位的问题。
2. 将五种状态组织成连续的情绪曲线，而不是“空、满、更满、空”的突变。
3. 让明暗形态切换可感知但不抢夺代码、终端、审批按钮和输入框的注意力。
4. 所有状态使用固定侧栏尺寸和稳定视觉锚点，不发生布局跳动。
5. 支持降动效、降透明度和快速状态切换。

## 不做的事

- 不在一个稳定画面中叠放剧情截图、卡面和透明立绘。
- 不恢复已移除的独立立绘素材。
- 不通过整页变暗表达错误或审批。
- 不使用循环呼吸、持续 glitch、闪烁、粒子庆祝或音效。
- 不修改 Codex 原生按钮、审批逻辑、状态判断优先级和可访问性语义。
- 本轮不上传远程 Registry。

## 美术与画面规则

任务侧栏只使用 `art/source/official/denia-poster-wide.png` 及其现有包内 WebP 衍生图。它是一个完整连续的官方舞台画面：

- `light-form` 固定裁出画面中的明形态，并保留同一裁切内的舞台环境。
- `dark-form` 固定裁出画面中的暗形态，并保留同一裁切内的舞台环境。
- 两层拥有相同的侧栏盒、人物视觉中心和底部基线；各自裁切一经确定，不随状态移动。
- 稳态只显示一个主体。两层同时可见只发生在短暂交叉淡化期间。
- 不把完整横图压缩成窄条，不把多个角色焦点同时塞入侧栏。

《旧日斑斓》暖色剧情帧继续只服务首页拍立得，不进入任务状态侧栏。

## 布局与分隔

### 宽屏

- 视口宽度不小于 `1180px` 时，侧栏宽度为 `clamp(280px, 20vw, 320px)`。
- 侧栏从任务页首次挂载起即预留空间；状态变化只改变内部图层，不改变宽度。
- 工作内容、滚动区和 composer 的右边界必须位于侧栏左侧，至少保留 `24px` 安全间距。
- 侧栏左边界使用 `1px` 低对比分隔线和 `32px` 单向渐隐。渐隐只能从工作区过渡到美术区，不能覆盖文字。

### 中等窗口

- `920px–1179px` 使用 `220px–260px` 侧栏。
- 人物透明度比宽屏目标值降低约 20%，安全间距不少于 `16px`。
- 如果无法通过已验证的原生容器选择器为内容预留空间，则隐藏人物层，只保留窄幅状态色边，不允许覆盖 composer。

### 小窗口

- 小于 `920px` 隐藏人物图层和侧栏占位。
- 状态仍由观察区文案、pill、边框色和气泡表达。
- 隐藏侧栏不影响状态检测或清理协议。

## 状态与情绪映射

主工作区保持接近原有浅色亮度，变化集中在侧栏、观察区、pill 和状态气泡。

| 状态 | 主要画面 | 目标透明度 | 色调 | 使用情绪 |
| --- | --- | ---: | --- | --- |
| `staged` | 无人物，保留纸张底纹 | `0` | 中性暖白 | 尚未开始、安静 |
| `working` | 明形态 | `.16` | 冷青、轻降饱和 | 专注、持续陪伴 |
| `approval` | 暗形态 | `.42` | 低饱和紫 | 悬停、等待决定 |
| `error` | 暗形态 | `.56` | 深紫与窄幅洋红边缘 | 警觉、需要处理 |
| `complete` | 明形态 | `.20` | 轻暖金高光 | 释然、记录归档 |

状态优先级保持 `error > approval > working > complete > staged`。错误的强度主要来自窄幅洋红边缘、状态文字和气泡，不靠把人物提高到不透明或压暗整个工作区。

## 图层结构

Sidecar 在现有装饰 chrome 内只创建一次状态侧栏：

```text
.denia-old-days-ds-state-art
├── .denia-old-days-ds-state-art-light
├── .denia-old-days-ds-state-art-dark
└── .denia-old-days-ds-state-art-tint
```

- `light` 与 `dark` 使用同一个包内舞台 WebP，只采用不同的固定裁切。
- `tint` 只负责状态色、左侧渐隐和一次性错误边缘，不承载人物。
- 三个节点在刷新时不重建，避免图片闪烁和对象 URL 泄漏。
- JS 继续只更新根节点的 `data-denia-form-state`；透明度、位移、滤镜和延迟由 CSS 状态规则驱动。
- CSS transition 被新状态打断时，应从当前计算值继续插值，不使用会回写旧状态的 timeout。

## 动画编排

一次完整切换最多 `900ms`，使用 `cubic-bezier(.22, 1, .36, 1)`。动画只使用 `opacity`、`transform` 和 `filter`，不改变盒模型。

| 时间 | 动作 |
| ---: | --- |
| `0–80ms` | 立即更新状态文字、可访问性语义与颜色 token。 |
| `80–220ms` | 状态气泡、观察区边框、pill 和页眉波纹换色。 |
| `120–420ms` | 旧形态降低透明度并向侧栏外轻移 `8px`。 |
| `220–620ms` | 新形态从目标锚点右侧 `12px`、`scale(.985)` 淡入并回到静止。 |
| `420–760ms` | tint、左侧渐隐和状态滤镜收束。 |
| `760–900ms` | 一次性阴影或错误色偏衰减，画面完全静止。 |

### 状态特例

- `staged → working`：只淡入明形态，不先制造暗场。
- `working → approval`：明形态退出后暗形态进入，紫色 token 先于人物完成切换。
- `approval → error`：保持暗形态锚点不变，只提高透明度、加深紫色并执行一次不超过 `120ms` 的洋红边缘色偏。
- `error → working`：直接回到明形态的冷青专注态，不保留错误残影。
- `working/approval/error → complete`：明形态回归，暖金只作用于高光、页眉波纹和 pill，不把工作区染黄。

## 可访问性与用户偏好

- `prefers-reduced-motion: reduce`：所有状态直接呈现终态；无位移、缩放、延迟、交叉淡化或色偏。
- `prefers-reduced-transparency: reduce`：降低人物目标透明度，使用更实的侧栏底色与分隔线，确保正文对比度不依赖毛玻璃。
- 状态变化不得抢焦点、修改 tab 顺序或创建可点击节点。
- 装饰层保持 `aria-hidden="true"` 与 `pointer-events: none`。
- 状态文字继续承担语义，人物形态不作为唯一状态信号。

## 快速状态切换

- 同一帧内的多次 DOM 变化只提交最终推导状态。
- CSS transition 可从当前进度转向新目标，不等待前一次动画结束。
- 不设置“必须播完”的动画锁。
- error 和 approval 的检测优先级保持现状，避免短暂 working 覆盖高优先级状态。
- cleanup 必须移除侧栏节点、样式、监听器和对象 URL；不得留下未完成计时器。

## 验收标准

1. `working` 显示低对比明形态，`complete` 显示同位明形态与轻暖金高光。
2. `approval` 与 `error` 使用同位暗形态，错误态更强但人物不超过 `.56`。
3. 侧栏在宽屏和中等窗口不覆盖原生任务内容或 composer。
4. 任意状态切换不引发布局跳动，最长在 `900ms` 内静止。
5. 快速连续切换不会出现旧状态回写、图片闪烁或残留动画。
6. 降动效模式直接呈现终态，状态仍可由文字和颜色辨识。
7. 小窗口隐藏侧栏后，任务页继续完整可用。
8. 运行时只读取包内资源，不发起图片网络请求。
9. Sidecar 清理、离线渲染、源结构检查和 Kaboo 构建验证继续通过。
