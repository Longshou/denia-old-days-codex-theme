# 达妮娅任务状态双形态转场设计

日期：2026-07-23

状态：方案 A 架构已确认；贺图/壁纸素材策略已修订，待确认后实施

本规格取代《达妮娅泡泡拍立得与双形态视觉设计》中“工作态与完成态不显示侧栏美术”的规则，也取代本规格早期“所有状态裁自同一张舞台海报”的素材方案。首页设计、拍立得和泡泡规则保持不变。

## 设计判断

任务页使用“稳定的浅色手账工作区 + 固定的单画面状态侧栏”。侧栏不再依赖角色 PV、演示 PV 或单张舞台海报，而是从官方发布的贺图、壁纸和纪念插画中选择少量、构图相容的近景画面。明暗形态由眼神锚点、脸部尺度、气泡/手势/人偶等叙事道具和统一的侧栏色彩曲线串联，而不是把不同来源的图片糅合成拼贴。

状态变化只在固定侧栏内发生，不改变 Codex 原生工作区的布局、亮度与交互层级。稳定画面始终只有一个主要人物焦点；不同素材只在短暂转场中交接，不能同时以相近强度出现。

- `DESIGN_VARIANCE: 5`
- `MOTION_INTENSITY: 5`
- `VISUAL_DENSITY: 5`

独立审查依据见[任务状态 UI/UX 审查](../../reviews/2026-07-23-denia-state-transition-ui-ux-review.md)。

## 目标

1. 消除 `working`、`complete` 右侧只剩纯色占位的问题。
2. 将五种状态组织成连续的情绪曲线，而不是“空、满、更满、空”的突变。
3. 让明暗形态切换可感知但不抢夺代码、终端、审批按钮和输入框的注意力。
4. 所有状态使用固定侧栏尺寸和稳定视觉锚点，不发生布局跳动。
5. 支持降动效、降透明度和快速状态切换。

## 不做的事

- 不在一个稳定画面中叠放剧情截图、卡面和透明立绘。
- 不恢复已移除的独立立绘素材。
- 不继续提取角色 PV、演示 PV 或战斗演示帧作为任务侧栏候选。
- 不把多人海报、完整横幅、带大面积宣传文字的卡面硬裁成窄条。
- 不采用“单独放一张全身立绘”作为任一稳定状态。
- 不因一张图偏暗就自动归入错误态；表情和动作语义优先于色相。
- 未明确获得再分发许可的同人贺图只进入参考库，不进入运行包。
- 不通过整页变暗表达错误或审批。
- 不使用循环呼吸、持续 glitch、闪烁、粒子庆祝或音效。
- 不修改 Codex 原生按钮、审批逻辑、状态判断优先级和可访问性语义。
- 本轮不上传远程 Registry。

## 美术与画面规则

运行包候选只从本地素材库 `production-ready/` 中选择已通过对应版式实裁的官方发布插画；上传 Registry 前仍需逐项确认来源与再分发边界。素材原图保留完整尺寸，不把“适合侧栏”误写成“所有资源都要裁成竖图”。

每个使用场景先选择版式，再选择素材：

- `rail-portrait`：任务侧栏、状态陪伴层。优先竖向近景、眼神交流和单一叙事道具。
- `wide-scene`：首页大图、空态叙事区、宽幅过渡。保留完整环境关系和横向动线，不强行裁脸。
- `feature-card`：拍立得、手账夹页和回忆卡。允许中景与场景细节，但文字必须属于主题排版，而不是原图宣传文案。
- 同一原图可以产生经审查的版式衍生图；源文件始终保留，运行包只携带当前版式所需的衍生图。

| 画面家族 | 本地候选 | 用途 | 构图判断 |
| --- | --- | --- | --- |
| 暖日陪伴 | `denia-garden-bubbles-warm.jpg` | `staged` / `working` | 正脸与视线朝向用户，泡泡、猫与玩偶保留生活感；作为两态共同母图避免频繁换画。 |
| 暗色审视 | `denia-dark-direct-gaze.jpg` | `approval` / `error` | 正脸无笑、目光严肃；审批态表达等待，错误态通过更强 tint、边缘和状态文字表达警觉。 |
| 暖色收束 | `denia-anniversary-direct-gaze.jpg` | `complete` | 竖版近景、轻微笑意与手势完整，适合完成后的正向回看；运行版必须放大并裁掉底部周年宣传字样。 |
| 双形态宽景 | `denia-dual-form-panorama.jpg` | `wide-scene` 候选 | 明暗形态和舞台关系完整，适合宽幅叙事；不硬裁成稳定侧栏。 |
| 晶球近景 | `denia-orb-closeup-dark.jpg` | 仅作交互构图参考 | 眼神、手和晶球的关系优秀，但角色带笑，不用于错误态。 |

每个稳定裁切必须同时满足：

- 双眼或主视线位于侧栏高度约 `24%–34%`，朝向用户或左侧工作区。
- 脸部与上半身占侧栏有效面积约 `25%–55%`，不能只剩局部五官，也不能缩成远景。
- 保留一个叙事道具，如泡泡、手势、晶球、猫或玩偶；不同时争夺人物焦点。
- 左侧使用 `32–48px` 单向渐隐和轻色罩，工作区与插画边界清楚；正文不直接压在插画上。
- 每张图拥有固定 `background-size` 与 `background-position` token；稳定状态中不平移找脸。
- 裁切后只要宣传标题、周年标、营销口号或大面积署名仍进入主要视觉区，就舍弃该版式；不得用模糊、重遮罩或压暗去掩盖污染。
- 情绪审查顺序为“眉眼与嘴角 → 头部朝向 → 手势/道具 → 明暗色相”。微笑、庆祝手势和松弛躺姿不进入错误态；警惕、严肃、观察或受阻的表情才可使用。

《旧日斑斓》暖色剧情帧继续只服务首页拍立得，是已确认的剧情特例；不再批量提取其余视频帧。官方发布的同人纪念插画只保留在 `reference-only/`，未经许可不进入运行包。

## 布局与分隔

### 宽屏

- 视口宽度不小于 `1180px` 时，侧栏宽度为 `clamp(280px, 20vw, 320px)`。
- 侧栏从任务页首次挂载起即预留空间；状态变化只改变内部图层，不改变宽度。
- 工作内容、滚动区和 composer 的右边界必须位于侧栏左侧，至少保留 `24px` 安全间距。
- 侧栏左边界使用 `1px` 低对比分隔线和 `32px` 单向渐隐。渐隐只能从工作区过渡到美术区，不能覆盖文字。

### 中等窗口

- `920px–1179px` 使用 `220px–260px` 侧栏。
- 人物透明度比宽屏目标值降低约 20%，安全间距不少于 `16px`。
- 如果无法通过已验证的原生容器选择器为内容预留空间，则隐藏人物层，只保留窄幅状态色边，不允许覆盖 composer。

### 小窗口

- 小于 `920px` 隐藏人物图层和侧栏占位。
- 状态仍由观察区文案、pill、边框色和气泡表达。
- 隐藏侧栏不影响状态检测或清理协议。

## 状态与情绪映射

主工作区保持接近原有浅色亮度，变化集中在侧栏、观察区、pill 和状态气泡。

| 状态 | 主要画面 | 目标透明度 | 色调 | 使用情绪 |
| --- | --- | ---: | --- | --- |
| `staged` | 暖日泡泡近景 | `.10–.12` | 中性暖白、低饱和 | 尚未开始、安静陪伴 |
| `working` | 同一暖日泡泡近景 | `.18–.22` | 冷青与粉色轻聚焦 | 专注、持续陪伴 |
| `approval` | 暗色正脸近景 | `.40–.46` | 低饱和紫 | 悬停、等待决定 |
| `error` | 同一暗色严肃正脸近景 | `.52–.58` | 深紫与窄幅洋红边缘 | 警觉、需要处理 |
| `complete` | 周年正脸近景 | `.24–.30` | 暖白与轻金高光 | 释然、回应、记录归档 |

状态优先级保持 `error > approval > working > complete > staged`。错误的强度主要来自窄幅洋红边缘、状态文字和气泡，不靠把人物提高到不透明或压暗整个工作区。

## 图层结构

Sidecar 在现有装饰 chrome 内只创建一次状态侧栏，并预加载三张包内稳定状态图：

```text
.denia-old-days-ds-state-art
├── .denia-old-days-ds-state-art-current
├── .denia-old-days-ds-state-art-next
└── .denia-old-days-ds-state-art-tint
```

- `current` 与 `next` 是两个相同尺寸的交换层，只读取状态表映射的包内图片和固定裁切 token。
- `tint` 只负责状态色、左侧渐隐和一次性错误边缘，不承载人物。
- 三个节点在刷新时不重建，避免图片闪烁和对象 URL 泄漏。
- `staged` 与 `working` 共享同一图片和同一裁切，只改变目标透明度、滤镜和 tint，不触发图片交换。
- 其他状态切换时，JS 把新图写入 `next`，CSS 完成单向交接后再更新 `current`；用递增 generation token 或 `transitionend` 拒绝旧状态回写，不依赖裸 timeout。
- 所有状态图片在 Sidecar 初始化后、侧栏显示前完成预解码；失败时退回状态色边，不发起远程请求。
- CSS transition 被新状态打断时，应从当前计算值继续插值；当前可见层成为新的离场层，新状态成为唯一入场层。

## 动画编排

一次完整切换最多 `900ms`，使用 `cubic-bezier(.22, 1, .36, 1)`。动画只使用 `opacity`、`transform` 和 `filter`，不改变盒模型。

| 时间 | 动作 |
| ---: | --- |
| `0–80ms` | 立即更新状态文字、可访问性语义与颜色 token。 |
| `80–220ms` | 状态气泡、观察区边框、pill 和页眉波纹换色。 |
| `120–420ms` | 旧形态降低透明度并向侧栏外轻移 `8px`。 |
| `220–620ms` | 新形态从目标锚点右侧 `12px`、`scale(.985)` 淡入并回到静止。 |
| `420–760ms` | tint、左侧渐隐和状态滤镜收束。 |
| `760–900ms` | 一次性阴影或错误色偏衰减，画面完全静止。 |

### 状态特例

- `staged → working`：同一暖日泡泡图只提高透明度和冷青聚焦，不发生换图。
- `working → approval`：暖日近景先退出，暗色正脸再进入；紫色 token 先于人物完成切换。
- `approval → error`：保持同一张无笑暗色正脸，只提高透明度、加深 tint，并执行一次不超过 `120ms` 的洋红边缘色偏；不因状态加重而换成带笑的晶球图。
- `error → working`：暗色严肃正脸退出后回到暖日泡泡图，不保留错误残影。
- `working/approval/error → complete`：周年正脸近景进入，暖金只作用于高光、页眉波纹和 pill，不把工作区染黄。
- 交接时旧图在新图达到目标透明度的一半前降到低于其一半，禁止两个脸部以相近强度形成拼贴。

## 可访问性与用户偏好

- `prefers-reduced-motion: reduce`：所有状态直接呈现终态；无位移、缩放、延迟、交叉淡化或色偏。
- `prefers-reduced-transparency: reduce`：降低人物目标透明度，使用更实的侧栏底色与分隔线，确保正文对比度不依赖毛玻璃。
- 状态变化不得抢焦点、修改 tab 顺序或创建可点击节点。
- 装饰层保持 `aria-hidden="true"` 与 `pointer-events: none`。
- 状态文字继续承担语义，人物形态不作为唯一状态信号。

## 快速状态切换

- 同一帧内的多次 DOM 变化只提交最终推导状态。
- CSS transition 可从当前进度转向新目标，不等待前一次动画结束。
- 不设置“必须播完”的动画锁。
- error 和 approval 的检测优先级保持现状，避免短暂 working 覆盖高优先级状态。
- cleanup 必须移除侧栏节点、样式、监听器和对象 URL；不得留下未完成计时器。

## 验收标准

1. `staged` 与 `working` 使用同一暖日泡泡近景和固定裁切；工作态只提高存在感，不硬切图片。
2. `approval` 与 `error` 使用同一暗色严肃正脸近景；错误态只加强 tint、边缘和状态语义，人物不超过 `.58`。
3. `complete` 使用周年正脸近景和轻暖金高光，底部宣传文字不进入有效画面。
4. 侧栏在宽屏和中等窗口不覆盖原生任务内容或 composer。
5. 任意状态切换不引发布局跳动，最长在 `900ms` 内静止。
6. 快速连续切换不会出现旧状态回写、图片闪烁或残留动画。
7. 降动效模式直接呈现终态，状态仍可由文字和颜色辨识。
8. 小窗口隐藏侧栏后，任务页继续完整可用。
9. 运行时只读取包内资源，不发起图片网络请求。
10. 稳态画面没有单独全身立绘、多人拼贴、大面积宣传文字或 PV/演示 PV 帧。
11. 错误态人物无微笑、庆祝或松弛表情；完成态允许轻微笑意和正向手势。
12. 横幅与场景图保留为 `wide-scene` 候选，不因侧栏方案被统一裁成竖图。
13. Sidecar 清理、离线渲染、源结构检查和 Kaboo 构建验证继续通过。
