# 达妮娅深色任务页文字与代码配色设计

## 设计目标

在不改变任务页布局、交互和内容结构的前提下，为深色主题补齐一套完整、成熟且贴合达妮娅紫蓝视觉的文字与代码语义色。

验收目标：

- 普通正文清晰、锐利，无白色辉光或模糊边缘。
- 标题、正文、辅助信息、链接和禁用信息具有稳定层级。
- 表格表头、表格正文、行内代码、代码块和纯文本图均可辨认。
- 语法高亮颜色协调，不依赖宿主浅色主题遗留值。
- 普通大小文字对比度不低于 `4.5:1`；正文、表格正文和代码正文目标不低于 `7:1`。
- 浅色主题、首页、终端、Diff、编辑器及非 Markdown 工作区保持不变。
- 不增加运行时监听、动画、网络请求或逐节点 JavaScript 着色。

## 现状与根因

当前深色主题仅定义了正文、弱化文字、焦点色等少量基础变量：

```text
--denia-dark-text
--denia-dark-text-muted
--denia-dark-focus
```

任务页又只对带有特定模块类名的段落、列表和标题设置了深色正文颜色。普通段落的实际计算色已经是 `#F3EFF6`，且文字阴影为 `none`；但 Markdown 内容容器仍保留浅色主题的深墨色 `#263548`。

以下内容不一定带有段落模块类名，因此继续继承容器颜色：

- 表格正文单元格；
- 纯文本代码块和树形图；
- 语法高亮器未单独着色的标识符和标点；
- Markdown 内部后续新增的结构化内容。

同时，部分表头或语法 token 可以拥有自己的颜色或文字阴影，单纯清除 Markdown 容器的阴影不足以覆盖这些节点。

因此本次修复必须建立完整的 Markdown 语义色层，不能继续逐个修补截图中的单一元素。

## 采用方向

采用已批准的方案 A：“达妮娅夜色 + 成熟编辑器配色”。

设计原则参考成熟暗色产品的共同做法：

- 使用功能语义色，而不是在选择器中散落原始色值；
- 保持有限色相，强调色只承担明确角色；
- 通过表面明度和文字层级建立结构，不使用文字外发光；
- 代码色彩服务于扫描和理解，不追求高饱和霓虹效果。

现有墨蓝紫画布和表面保持不变。此次只完善文字、Markdown 表面及代码语法颜色。

## 深色文字语义色板

| 语义变量 | 色值 | 用途 |
| --- | --- | --- |
| `--denia-dark-text-heading` | `#F3EFF6` | 标题、表头和主要强调文字 |
| `--denia-dark-text-body` | `#E7E3EC` | 普通正文、列表和表格正文 |
| `--denia-dark-text-secondary` | `#BBB5C9` | 时间、说明和次级操作 |
| `--denia-dark-text-tertiary` | `#9E98AE` | 非关键元数据和占位信息 |
| `--denia-dark-text-link` | `#8DC5EA` | 链接、可交互引用和焦点信息 |

保留现有兼容变量，但将其映射到新的语义层：

```text
--denia-dark-text       -> --denia-dark-text-heading
--denia-dark-text-muted -> --denia-dark-text-secondary
--denia-dark-focus      -> --denia-dark-text-link
```

普通正文不再直接使用标题级的 `#F3EFF6`，改用略柔和的 `#E7E3EC`，降低大面积高亮造成的刺眼感，同时保持高对比度。

## 深色代码语义色板

| 语义变量 | 色值 | 用途 |
| --- | --- | --- |
| `--denia-dark-code-text` | `#D7D9E8` | 未分类 token、变量和纯文本代码 |
| `--denia-dark-code-comment` | `#8F97B5` | 注释和非执行说明 |
| `--denia-dark-code-keyword` | `#C7A7E8` | 关键字和控制流 |
| `--denia-dark-code-type` | `#91C9F2` | 类型、类、属性和可调用符号 |
| `--denia-dark-code-string` | `#9DD8C5` | 字符串和文本字面量 |
| `--denia-dark-code-constant` | `#F0B2CE` | 数字、布尔值、枚举和常量 |
| `--denia-dark-code-punctuation` | `#B6BCD2` | 运算符、括号和标点 |
| `--denia-dark-code-warning` | `#F0CC8C` | 警告和需要注意的 token |
| `--denia-dark-code-surface` | `#191C38` | Markdown 代码块背景 |
| `--denia-dark-code-inline-surface` | `#272A50` | 行内代码背景 |

色彩角色：

- 蓝色承接晶体、记忆泡泡和冷色反光；
- 薰衣草紫用于关键字，呼应达妮娅的紫蓝造型；
- 柔粉用于常量和数值，避免当前高饱和红色产生错误提示感；
- 低饱和青绿色仅用于字符串；
- 默认代码文字和标点使用偏冷中性色，保证长代码块阅读稳定。

## 对比度

基于现有深色画布和表面，设计色板的关键对比度如下：

| 前景 / 背景 | 对比度 |
| --- | ---: |
| `#E7E3EC` / `#12142F` | `14.22:1` |
| `#BBB5C9` / `#202348` | `7.57:1` |
| `#9E98AE` / `#202348` | `5.42:1` |
| `#D7D9E8` / `#191C38` | `11.85:1` |
| `#8F97B5` / `#191C38` | `5.74:1` |
| `#C7A7E8` / `#191C38` | `8.00:1` |
| `#9DD8C5` / `#191C38` | `10.33:1` |
| `#F0B2CE` / `#191C38` | `9.46:1` |
| `#91C9F2` / `#191C38` | `9.36:1` |

所有承担信息的普通大小文字均高于 WCAG AA 的 `4.5:1` 阈值。

## 渲染规则

### Markdown 基础层

深色任务页的 Markdown 内容根节点设置正文色和无文字阴影，解决结构化子节点继承浅色墨色的问题。

标题使用标题色；段落、列表、引用和表格正文使用正文色；辅助说明使用次要或弱化色。所有 Markdown 文本后代清除 `text-shadow`，不改变 `font-family`、字号、字重、行高或字距。

### 表格

- 表头使用标题色，不使用发光或阴影。
- 表格正文使用正文色。
- 分隔线使用现有深色分界线变量。
- 不改变表格宽度、单元格间距、对齐或滚动行为。

### 行内代码

- 文字使用链接/晶体蓝。
- 背景使用 `--denia-dark-code-inline-surface`。
- 保留宿主现有圆角、内边距和字体。
- 不把普通链接或文件路径误判为行内代码。

### 代码块

- 只作用于 Markdown 内容内部的 `pre` 和代码高亮节点。
- 代码块基础文字使用 `--denia-dark-code-text`，确保未分类 token 可见。
- 背景使用 `--denia-dark-code-surface`。
- 语言标签和复制按钮使用次要文字色，交互态使用链接色。
- 语法 token 按已批准的代码色板映射。
- 若宿主 token 使用内联颜色或 CSS 变量，实施时优先覆盖宿主语义变量；只有无法稳定映射时才在 Markdown 作用域内覆盖 token 类。

### 文字锐度

- Markdown 内容、表格和代码块均明确设置 `text-shadow: none`。
- 不使用 `filter`、`backdrop-filter`、`-webkit-text-stroke` 或变换来增强文字。
- 不修改系统字体平滑设置，避免不同显示器和操作系统出现不可控差异。

## 作用范围与排除项

所有新规则必须同时满足：

```text
深色主题
任务页面
原生任务主栏
Markdown 内容作用域
```

明确排除：

- 浅色主题；
- 深色首页 Hero 和首页建议卡；
- 原生终端；
- Diff 查看器；
- 代码编辑器；
- 日志、工具输出和原生侧栏；
- 输入框、模型选择器和权限控件；
- 现有任务背景、美术素材和状态卡布局。

原有验证器禁止深色可读性规则宽泛命中 `code`、`pre`、终端和编辑器。本次只把例外收窄到 Markdown 内容内部的代码表面；终端、Diff 和编辑器禁区继续保留。

## 性能与兼容性

- 使用静态 CSS 变量和选择器完成适配。
- 不新增 MutationObserver、事件监听、定时器或动画。
- 不遍历或逐节点写入运行时样式。
- 不加载字体、图片或远程资源。
- 不改变 DOM，不影响复制、选择、滚动和键盘操作。
- 模块类名变化时，Markdown 内容根选择器沿用当前已验证的稳定片段匹配方式。

## 验证方案

### 静态验证

- 检查所有文字与代码语义变量存在且色值固定。
- 检查新规则仅位于深色任务 Markdown 作用域。
- 检查终端、Diff、编辑器和浅色主题未被命中。
- 检查不存在布局属性、动画、滤镜或运行时功能改动。
- 调整验证器的代码禁区断言：只允许 Markdown 内部的明确例外。

### 构建验证

- 运行仓库现有源码检查。
- 运行 sidecar 结构验证。
- 构建完整 sidecar 包，确认 CSS 可被解析和注入。

### 实机验证

在当前 Codex 深色主题中分别检查：

1. 多段中文正文和项目列表；
2. 含表头、普通单元格、行内代码和链接的表格；
3. TypeScript 代码块；
4. 未指定语言的纯文本代码块和树形图；
5. 长代码块、语言标签和复制按钮；
6. 同一任务切回浅色主题；
7. 终端、Diff 和编辑器保持原生颜色。

记录正文、表格和代码块的计算色、文字阴影和背景色，并提供实机截图对比。
