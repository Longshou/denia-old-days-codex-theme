# 首页原生提示区移除

## 问题

首页同时显示两套相同意图的内容：

- 主题 Hero 已经展示“今天要把什么写进手账？”和当前项目语境。
- Codex 原生提示区继续展示“What should we build in …?”和行内项目入口。
- 主题四张建议卡与原生提示区占用同一段首页空间，出现视觉重叠。

原生提示区属于重复内容。项目选择器和输入框仍需保留。

## 方案

复用运行时已有的 `syncNativeHomePrompt` 识别能力，在四个语义动作完整、主题建议卡成功挂载时，为原生提示区外层添加 `denia-old-days-ds-native-home-prompt`。

现有 CSS 使用 `display: none !important` 隐藏该外层。运行时不删除或移动 Codex 节点。

识别范围从标题文本向上扩展，止于原生建议按钮所在容器之前，因此会隐藏：

- 英文提示标题。
- 标题行内的项目入口。
- 标题区自身的占位高度。

不会隐藏：

- 四个原生动作按钮的容器。该容器继续作为主题卡片的真实点击目标。
- 主题 Hero 和主题四卡片。
- 输入区附近的项目选择器。
- 输入框、权限选择和模型选择。
- 任务页内容。

## 生命周期

- 原生动作恰好覆盖四个语义类别时，先创建或更新主题四卡片，再隐藏原生提示区。
- 原生动作不足四个或语义类别不完整时，移除主题卡片并恢复原生提示区。
- 离开首页、卸载主题或执行清理时，移除隐藏类并恢复原生节点。
- 重复刷新不得重复写入相同 class，也不得复制事件监听器。

## 验证

- 静态校验要求 `ensureSuggestionDeck` 在四动作分支调用 `syncNativeHomePrompt`。
- 运行时测试使用接近实机的标题、行内项目按钮和外层结构。
- 四张主题卡片挂载后，原生提示外层必须带隐藏类。
- 动作不足四个、离开首页和清理后，隐藏类必须消失。
- 实机首页必须保留四张主题卡、项目选择器和输入框，同时不再显示英文原生提示区。
- 完整源码检查、Kaboo 构建和 Sidecar 实机验证必须通过。

## 验收标准

- 首页不再显示“What should we build in …?”原生提示区。
- 四张主题卡不再与原生提示区重叠。
- 项目选择器、输入框和任务页没有布局或交互回归。
- 主题卸载后 Codex 原生首页结构可以完整恢复。
