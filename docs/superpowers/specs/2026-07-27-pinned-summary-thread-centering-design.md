# 置顶摘要打开时的任务主栏居中修复

## 问题

任务页在右侧置顶摘要打开后，正文与输入框贴近左侧导航，未在剩余工作区内居中。

主题当前为右侧美术栏预留水平空间：

```css
margin-inline-start: max(
  16px,
  calc((100% - var(--thread-content-max-width) - var(--denia-state-rail-width)) / 2)
);
```

置顶摘要打开时，运行时会把 `data-denia-work-surface-state` 设为 `open` 并隐藏美术栏，但上述布局规则仍然生效。可用宽度缩小后，计算结果落到 `16px`，主栏被压到左侧。

## 设计

- 自定义水平对齐只在以下条件同时成立时生效：
  - 当前为任务页。
  - 原生右侧栏关闭。
  - 所有原生工作面板关闭。
- `data-denia-work-surface-state="open"` 时，不覆盖主栏的原生 `margin-inline`。
- 置顶摘要打开后，由 Codex 原生布局在左侧导航与右侧摘要之间的剩余空间内居中主栏。
- 不修改主栏宽度、摘要面板宽度、输入框尺寸或任务状态美术。
- 不增加 DOM 测量或运行时边距计算。

## 测试

在现有 CSS 验证中增加以下断言：

- 自定义任务主栏选择器必须包含 `[data-denia-work-surface-state="closed"]`。
- 该选择器继续保留现有的美术栏预留计算。
- 不允许新增面向 `open` 状态的任务主栏布局覆盖。

先让测试因缺少 `data-denia-work-surface-state="closed"` 而失败，再收窄 CSS 选择器并运行完整验证。

## 验收标准

- 摘要关闭且右侧美术栏可见时，主栏保持当前对齐。
- 摘要打开时，主栏在剩余工作区内居中，不贴近左侧导航。
- 摘要反复开关后，布局随状态恢复。
- 右侧美术栏、右侧原生面板和输入框交互不受影响。
- Sidecar 全量验证通过。
